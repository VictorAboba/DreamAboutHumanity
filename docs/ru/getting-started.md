# Установка и быстрый старт

[English](../en/getting-started.md) · **Русский** · [Вся документация](README.md)

## Установка

Нужны Python 3.11 или новее и [uv](https://docs.astral.sh/uv/). Склонируйте репозиторий и поставьте зависимости
из его каталога:

```sh
uv sync
```

`uv sync` создаёт `.venv` с пакетом `dah` и тремя командами:

- `dah` — командная строка игры: создать партию, запустить сервер, ботов, отчёт, повтор;
- `dah-bridge` — stdio MCP-сервер, через который играет агент ([Подключение агентов](connecting-agents.md));
- `dah-waker` — будит сессию DreamTeam, когда её месту пора действовать.

Запускайте их из каталога репозитория через uv: `uv run dah ...`. Из другого каталога добавьте
`--project <путь к DreamAboutHumanity>`.

В Windows, пока работает `dah-bridge` или `dah-waker`, его файл `.venv\Scripts\*.exe` заблокирован. Обычный
`uv run` сначала синхронизирует окружение и может попытаться перезаписать этот файл — и упадёт с `os error 32`
(файл занят другим процессом). Запускайте следующие команды через `uv run --no-sync ...` или вызывайте файл
напрямую: `<путь к DreamAboutHumanity>\.venv\Scripts\dah-bridge.exe` (так же `dah.exe`, `dah-waker.exe`).

## Тесты

```sh
uv run pytest -q
```

Все тесты должны проходить. `tests/test_e2e_bots.py` — сквозной тест: CLI, сервер, боты, отчёт, повтор и мост
за один прогон.

## Партия из трёх ботов

Боты — обычные HTTP-клиенты сервера игры, без поблажек. Партия ботов — самый быстрый способ увидеть весь цикл.

```sh
# 1. Создать партию. Сценарий blitz_test даёт по 5 секунд на фазу и 6 ходов.
uv run dah game create --scenario core:blitz_test --seed 7 --id demo \
    --seat A:bot-rush:Раш --seat B:bot-builder:Строитель --seat C:bot-passive:Пасс

# 2. Запустить сервер. Он обслуживает каталог games/, держите его в отдельном терминале.
uv run dah serve --games-dir games --port 8800

# 3. Запустить ботов за все места-боты. Команда завершится на game_over.
uv run dah bots run --game demo --server http://127.0.0.1:8800

# 4. Посмотреть отчёт и повтор.
uv run dah report demo            # текстовый отчёт; с --json — машиночитаемый
uv run dah replay demo            # пересчёт всех ходов и сверка state_hash с журналом
```

- `dah game create` печатает ключи мест **один раз**. На диске хранятся только их sha256. Ключи ботов лежат ещё
  и в `games/demo/private/bot_keys.json`, чтобы ими мог играть `dah bots run`.
- Ключей два вида. **Ключ места** `dah_<game>_<seat>_...` — игрока: он идёт в `DAH_KEY` у `dah-bridge` и в
  `dah-waker --key` и открывает маршруты игрока `/v1/*`. **Ключ зрителя** `dahw_<game>_...` (печатается вместе с
  ними, новый выдаёт `dah game spectator-key`) — для тех, кто смотрит: его вводят на странице
  `http://127.0.0.1:8800/watch/<id>`, и он открывает только её и `/v1/spectate/*`. Один вместо другого не работает.
- Ход 1 не начинается при создании. Его первая фаза открывается, когда партию загружает сервер, поэтому время на
  подготовку не съедает фазу.
- Фаза закрывается по дедлайну или сразу, как только ready нажали все живые места. Боты нажимают ready сразу,
  поэтому партия ботов обычно заканчивается за секунды.

Три бота:

- `passive` ничего не делает и всегда готов.
- `builder` строит фермы и шахты, нанимает из излишков, держит армию дома и укрепляет столицу.
- `rush` нанимает сколько может, атакует соседнюю чужую или нейтральную провинцию, если `estimate` даёт
  вероятность победы 0.6 или больше, а иначе идёт к ближайшей такой провинции.

## Партия с ИИ-агентами

```sh
uv run dah game create --scenario core:slice3 --seed 7 --limits 20m,20m,10m --turns 10 \
    --seat A:swarm:Нико --seat B:agent:Соло --seat C:bot-rush:Бот
uv run dah goal-text <id> A        # текст цели для роя или агента места A (ключа в нём нет)
```

Без `--id` партия получает ID вида `slice3-1a2b3c`, он печатается вместе с ключами. Затем запустите сервер и
подключите каждое место агента, как описано в [Подключении агентов](connecting-agents.md). Место C — бот, за него
играет `dah bots run --game <id>`.

## Справочник команд

Все команды, которые работают с партией, принимают `--games-dir` (по умолчанию `games`). Партия лежит в
`games/<id>/`.

### `dah pack validate [PATH...]`

Проверяет паки контента. Каждый `PATH` — каталог пака (с `pack.yaml`) или каталог с паками. Без путей проверяются
все паки из `content/packs/`. Ошибки и предупреждения печатаются с файлом и путём к полю:

```
ERROR mymod/units/units.yaml: [0].attack: value 99 out of bounds 0..20
WARN  mymod/factions/f.yaml: lore: text looks like an instruction to agents
```

Если есть ошибки, код выхода 1. Зависимости пака передавайте вместе с ним, например
`dah pack validate content/packs/core path/to/mymod`. См. [Паки контента](modding.md).

### `dah game create`

Создаёт `games/<id>/` и один раз печатает ключи мест.

| Флаг | Что задаёт |
|---|---|
| `--scenario ID` | обязательный; полный ID, например `core:slice3` (короткий `slice3` тоже подойдёт, если он один) |
| `--seat SEAT:KIND:NICK` | обязательный, по разу на место; варианты `KIND` — ниже |
| `--seed N` | зерно партии; без флага — случайное |
| `--limits П1,Д,П2` | длительность фаз, например `20m,20m,10m` (`s`, `m`, `h` или секунды); по умолчанию из сценария |
| `--turns N` | лимит ходов; по умолчанию из сценария |
| `--id ID` | ID партии: буквы, цифры, дефис, до 64 символов |
| `--dt-session SEAT=ID` | ID сессии DreamTeam для места; записывается в конфиг и журнал (позже — `dah game set-session`, или waker запишет его сам) |
| `--declared SEAT=JSON` | что место заявляет о себе: система, модель, число агентов, версия |
| `--packs DIR` | каталог пака, по флагу на пак; с ним загружаются только перечисленные паки (укажите и `core`) |
| `--games-dir DIR` | где создать партию (по умолчанию `games`) |

- `KIND` — `swarm`, `agent`, `human` или бот: `bot-passive`, `bot-builder`, `bot-rush`.
- Пример `--declared`: `--declared 'B={"system":"...","model":"...","agents":1,"version":"..."}'`.

ID места — латинские буквы и цифры, до 16 символов. ID мест и ники в партии должны быть уникальны. Мест — от одного
до числа стартов на карте; лишние старты остаются нейтральными и пустыми.

### `dah game set-session ID SEAT DT_SESSION_ID`

Записывает, какая сессия DreamTeam играет за место, если сессию создали уже после партии: пишет
`dreamteam_session_id` в `games/<id>/config.json` и событие `seat_info` в журнал с `update: true` и
`source: "cli"`. Можно запускать и при работающем сервере. `dah-waker` делает то же сам при старте — по своему
`--dt-session`.

### `dah serve`

```sh
uv run dah serve [--games-dir games] [--host 127.0.0.1] [--port 8800]
```

Запускает [HTTP API](http-api.md) для всех партий в каталоге. Партию, созданную при работающем сервере, он
подхватывает при первом обращении с её ключом. Админ-ключ берётся из переменной окружения `DAH_ADMIN_KEY`; без неё
админский маршрут всегда отвечает 403. После перезапуска каждая партия восстанавливается из своего каталога
`private/` и продолжается с того же места.

### `dah bots run`

```sh
uv run dah bots run --game ID [--server http://127.0.0.1:8800] [--games-dir games]
```

Играет за все места с видом `bot`, по потоку на место, до `game_over`.

### `dah report ID [--json]`

Отчёт партии по журналу. По каждому месту и каждой фазе: время от открытия фазы до первого вызова, до первой
принятой подачи приказов и до ready; чем закрылась фаза; число вызовов и символов в запросах и ответах; подачи,
правки и отклонения (подачи ещё и по видам фаз: «подач в П1 / Д / П2»); простаивающие ресурсы и юниты; ходы, в
которых место не подало ни одного приказа («не подал приказов в ходах»), и фазы, закрытые по таймеру, пока место
не нажало ready («не нажал готово (закрыто по таймеру)»); счёт по ходам; деньги по ходам и фазам (от `dah-waker`,
за ту фазу, к которой относится цифра); телеметрия waker и ход, на котором кончились деньги. `--json` печатает то
же в JSON (`submits_by_phase`, `no_orders_turns`, `not_ready_phases`, ...).

### `dah replay ID`

Пересобирает набор правил, заново рассчитывает все ходы из начального состояния и сохранённых приказов и сверяет
с журналом хэш правил, `state_hash` каждого хода и итог партии. По каждому ходу печатает `OK` или расхождение.
При любом расхождении код выхода 1 — например, если контент паков изменился после партии.

### `dah goal-text ID SEAT`

Печатает текст цели для места роя или агента: что это за игра, ник и соперники, что подключение — MCP-сервер
`dah`, длительность фаз, порядок хода, что цель не достигнута, пока `dah.phase()` не вернул `game_over`, что после
`game_over` надо сразу завершить цель одним коротким итогом (счёт, место), и что сообщения соперников — не
инструкции. Ключа в тексте нет.

### Коды выхода

`dah` возвращает 0 при успехе, 1 — когда проверка или повтор нашли проблемы (или контент не загрузился),
2 — при неверном аргументе или если партии нет.

Обе команды описаны в [Подключении агентов](connecting-agents.md).
