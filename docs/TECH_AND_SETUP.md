# Этап 2: дерево технологий, фаза старта, фракции — спецификация

Решения пользователя: CONCEPT.md, пункты 19–20. Всё ниже — расширение среза (SLICE.md). Если этот файл и код
расходятся, прав этот файл. Принципы прежние: ядро ничего не знает о конкретном контенте, всё — данные модулей,
детерминизм, туман войны на сервере, журнал пишет всё.

## 1. Расширения движка

### 1.1. Третий ресурс и роль `research`

- Новая роль ресурса `research`: очки исследования. Ресурс этой роли копится как обычный, но тратится только на
  технологии (приказ `research`). Роль необязательна: сборка без неё допустима, тогда технологии недоступны.
- В `core` — ресурс `creed` «Кредо» с ролью `research`. Источники: столица (+2; после прогона баланса +3, раздел 8), здание `temple` «Храм» (+3),
  тип провинции `shrine` «Святыня» (+3). Числа подбирает прогон баланса.

### 1.2. Юниты

Новые необязательные поля:

| Поле | Смысл |
|---|---|
| `move` | дальность хода по своей территории (по умолчанию 2, как в CONCEPT; в наборе без технологий, веток и артефактов — 1, как в срезе), по чужой всегда 1 |
| `requires: {tech: [...], building: [...]}` | без технологии юнит нельзя нанять; `building` — здание в провинции найма |
| `factions: [...]` | уникальный юнит: доступен только этим фракциям |
| `abilities: [...]` | способности из реестра движка (ниже) |

Способности (реестр, расширяемый): `ignore_fortify` (укрепление защитника не действует против этого юнита),
`siege` (множитель обороны столицы/Цитадели против него ×1, а не ×1.5), `garrison` (+X к обороне, когда стоит
в своей провинции, X — характеристика), `fast` (в чужой провинции 2 ребра). Способность — флаг + характеристики
вида `unit.<id>.ability.<name>.<param>`, чтобы модули и технологии могли их менять.

### 1.3. Здания

- `requires: {tech: [...]}`, `factions: [...]`.
- В контексте здания разрешён `modify` с областью действия `scope: province | owner`:
  `{effect: modify, target: province.defense_mul, op: add, value: 0.25, scope: province}`,
  `{effect: modify, target: command_points, op: add, value: 1, scope: owner}`.
- Новые адресуемые характеристики провинции: `province.defense_mul`, `province.income_mul.<res>`,
  `province.recruit_discount`. Скидка найма считается на одну единицу и округляется в пользу игрока (цена
  единицы — вниз), затем умножается на число: один приказ на N стоит столько же, сколько N приказов по одному.

### 1.4. Технологии (`techs/*.yaml`)

```yaml
id: deep_drilling
name: { ru: "Глубинное бурение", en: "Deep Drilling" }
branch: industry            # ветка из branches/*.yaml (название, порядок, цвет)
tier: 1                     # эпоха/ярус — для отображения и правил «нужно N технологий яруса»
cost: 30                    # в ресурсе роли research
requires: [ ]               # технологии
requires_any: [ ]           # хотя бы одна из
factions: [ ]               # пусто = всем
effects:                    # passive-эффекты владельца
  - { effect: modify, target: resource.core:alloy.income_mul, op: mul, value: 1.2 }
unlocks: [ ]                # чисто информационно (что открывает) — движок сам видит requires у юнитов/зданий
lore: lore/deep_drilling.md
```

- `branches/*.yaml`: `id, name, order, description`.
- Приказ `research {tech}` — только в фазе Д (в П1 только `validate`). Одна активная технология; очки ресурса
  `research` переводятся в неё в шаге экономики. Переключиться можно, прогресс по каждой технологии сохраняется.
  Излишек переходит на следующий ход в запас ресурса.
- Технология завершается в шаге «Исследования» расчёта, эффект действует со следующего хода.
- Фракция может менять цену технологий: характеристика `tech.<id>.cost` и `tech.branch.<branch>.cost_mul`.
- Туман: свои технологии видны полностью; чужие — нет (позже их раскроет шпионаж). Публично: число изученных
  технологий у каждого игрока (это в Летописи и для зрителя).
- Очки науки (этап 4, SCORING.md 2.2): когда у источника «наука» вес > 0, каждая изученная технология даёт
  `score.science.tier<N>` очков по своему ярусу (ярусы выше 4 — как 4-й), полная ветка — ещё `score.science.branch`.
  Очки за ярус даёт только изученное приказом `research` (`scoring.researched`): технологии, данные артефактом или
  стартом фракции (`grant_tech`), очков яруса не дают, но засчитываются для полной ветки. Свои очки науки — в
  `list_techs` (`science`), чужие под туманом «?».

### 1.5. Хуки и эффекты (реестр)

Добавить контексты `tech` (как `passive`) и `artifact` (passive + on_game_start), эффект
`unlock {kind: unit|building|order, id}` для того, что нельзя выразить через `requires`, и `grant_tech {tech}`
(для артефактов и стартовых наборов).

## 2. Фаза старта (`setup`)

Новая фаза перед ходом 1: `setup → negotiation_1 (ход 1) → …`. Свой лимит времени в сценарии
(`phase_limits.setup`, по умолчанию 5m), кнопка «Готово», автопилот.

Что делает игрок:

1. **Выбор фракции** из списка, разрешённого сценарием (`factions: [...]`). Сценарий задаёт
   `unique_factions: true|false` — может ли одна фракция достаться двоим. При `true` конфликт двух одинаковых
   выборов решается по seed, проигравший получает свой следующий вариант из списка предпочтений.
   Поэтому игрок подаёт **список предпочтений** (`choose_faction([...])`), а не одну фракцию.
2. **Выбор артефакта** (бонус на старт). Решение пользователя: два режима, выбираются при запуске партии.
   Значение по умолчанию задаёт сценарий, а хост переопределяет его при создании партии:
   `dah game create ... --artifacts draft|points|none [--artifact-offer 3] [--artifact-points 3]`
   (один сервер ведёт много партий, поэтому настройка — у партии, а не у процесса сервера). Режимы:
   - `draft` (по умолчанию): каждому месту по seed предлагается 3 случайных артефакта из пула, игрок берёт 1.
     Наборы подбираются так, чтобы суммарная сила (`power`) предложений у всех мест была примерно равна;
   - `points`: у каждого бюджет очков (например 3), артефакты стоят 1–3 очка, можно взять несколько;
   - `none`: без артефактов.
3. Кнопка «Готово». Не выбрал — первая фракция списка сценария (с учётом уникальности) и первый артефакт из
   предложенных.

Что видно:
- Во время фазы старта игрок видит все фракции и свои предложенные артефакты (`get_setup()`), полные описания
  (`describe(id)`), но не выбор соперников.
- После закрытия фазы фракции всех игроков публичны (они видны в состоянии и Летописи), артефакты — скрыты
  (раскрываются после партии; позже — шпионажем).

### Артефакты (`artifacts/*.yaml`)

```yaml
id: ember_relic
name: { ru: "Тлеющая реликвия", en: "Ember Relic" }
power: 2                    # сила для честной раскладки драфта; проверяется валидатором по эффектам
cost: 2                     # для режима points
factions: [ ]               # ограничение (пусто = любой фракции)
exclusive_with: [ ]         # нельзя вместе в режиме points
effects:
  - { effect: grant_tech, tech: deep_drilling }
  - { effect: add_resource, resource: core:alloy, amount: 20 }
lore: lore/ember_relic.md
```

Примеры пула `core` (около 12): стартовая технология, лишняя армия, +1 ОК навсегда, скидка на ветку технологий,
постоянный +доход одного ресурса, Цитадель в столице с начала, уникальный «наёмный» юнит, разведка соседей на
старте, уменьшенный штраф «наспех».

## 3. Контент `core` этого этапа

- **Фракции (5)** из CONCEPT.md, каждая с асимметрией через данные: бонусы-характеристики, 1 уникальный юнит или
  здание, своя дешёвая ветка технологий, минус. Нынешний «Завет Предела» остаётся нейтральной фракцией для тестов.
- **Юниты:** 6–8 общих (с учётом уже существующих) + 5 уникальных (по одному на фракцию).
- **Здания:** + Храм, Кузня (открывает тяжёлые юниты), Цитадель, Склад, Штаб.

- **Артефакты:** около 12.
- **Сценарии:** `slice3`/`slice2` получают `setup` с `draft`; `blitz_test` — `setup: none` (быстрые тесты).

## 4. API, мост, правила

- Новые маршруты/инструменты: `get_setup`, `choose_faction(prefs)`, `choose_artifacts(ids)`, `list_techs`
  (дерево: доступные/изученные/прогресс/цена), `describe(id)` (любой контент партии по ID или названию).
- Приказ `research` — обычный приказ (`validate_orders`/`submit_orders`).
- `rules()` растёт — поэтому правила разбиваются по темам: `rules()` — короткое ядро (≤ 6000 символов) с оглавлением,
  `rules(topic="techs"|"factions"|"artifacts"|"pacts"|...)` — подробности, собранные из контента партии.
- Боты: выбирают фракцию по своему стилю, артефакт по простой оценке, исследуют по фиксированному приоритету веток.
  Дипломат и симулятор баланса учитывают технологии.
- Зритель: фаза старта в шапке; фракции игроков в легенде; вкладка «Технологии» (для админа и после партии —
  изученное и прогресс; для зрителя с задержкой — только число изученных).
- Журнал: `setup_choice` (место, предпочтения, итог — приватно до конца фазы), `setup_closed`, `research_started`,
  `tech_completed`. Отчёт: фракция и артефакт места, технологии по ходам.

## 5. Совместимость

- Новые поля необязательны: старые модули валидны.
- Числа `core` меняются → `ruleset_hash` новый; повтор старых партий требует старой версии пакета (как и после
  прогона баланса). Замороженные версии лежат в `content/legacy/<id>-<версия>` (сейчас `core-0.2.0`); `dah replay`
  и `Game.load` берут их сами, когда хэш журнала совпадает (раздел 10).
- Сценарий с `setup: none` и одной фракцией — без фазы старта и выбора фракций, как срез. Набор паков без технологий,
  веток и артефактов (срез, `core` 0.2.0) ходит на 1 ребро: `unit.<id>.move` по умолчанию 1 (`Ruleset.move_default`,
  выводится из хэшируемого контента и в хэш не входит), так идущая партия 0.2.0 сохраняет свои правила хода. С
  контентом этапа 2 (в том числе `core:blitz_test` из `core` 0.3.0) — по умолчанию 2.

## 6. Как реализовано в движке (шаг «движок и Game»)

Где что: `engine/registry.py` (роли, характеристики, способности, контексты эффектов), `engine/content.py` (загрузка
`techs/`, `branches/`, `artifacts/`, новые поля, `Profile`), `engine/techs.py` (ключ характеристик места, доступность,
дальность хода, исследования), `engine/setup.py` (фаза старта), `engine/catalog.py` (описания, `describe`),
`engine/combat.py` (способности в бою), `game.py` (фаза `setup`, методы Game). Тестовый пак — `tests/packs/t2`.

**Совместимость.** Новые поля сущностей пустые по умолчанию и не входят в `ruleset.hash`, пока пусты; новые поля
игрока (`techs`, `research`, `researching`, `artifacts`) не входят в `state_hash`, пока пусты; новые глобальные
характеристики (`province.*`) не попадают в таблицы. Поэтому `core` без нового контента хэшируется как раньше, а
повтор старых партий сходится. Режим артефактов и лимит фазы старта — настройки партии (конфиг), не правила (не в хэше).
Тексты для людей — `lore`, `description`, `name_en`, `color` — в хэш не входят никогда (правка файла лора не ломает
повтор); только `lore` фракции остаётся в хэше набора без технологий, веток и артефактов, как было до этапа 2.

**Эффекты.** Ключ `effect:` — синоним `type:`. Контексты: `tech` (modify, income, unlock, set_flag), `artifact`
(modify, income, unlock — пассивно на всю партию; add_resource, grant_units, grant_building, set_flag, grant_tech — один
раз при создании хода 1), `on_game_start` фракции получает `grant_tech`, `building` — `income` и `modify` с
обязательным `scope: province | owner` (для `province` цель — только `province.*`). `unlock {kind: unit|building}`
снимает требования технологий и фракции (не здания в провинции найма); `unlock {kind: order, id}` делает этот вид
приказа закрытым для всех, пока его не откроет технология или артефакт (`NOT_AVAILABLE`).

**Характеристики места.** `stat_key(state, ruleset, seat)` — id фракции, пока у места нет технологий, артефактов и
зданий со `scope: owner`, иначе `Profile` (фракция + технологии + артефакты + число таких зданий). Модификаторы
складываются в порядке: overrides сценария → фракция → технологии (по id) → артефакты (по id) → здания (каждое
здание — один раз). Расчёт берёт ключи на начало расчёта: изученное в нём действует со следующего хода (и ОК тоже).
Характеристика провинции = значение владельца + `modify` зданий со `scope: province` в ней. Новые характеристики:
`unit.<id>.move` (1..5, по умолчанию 2; в наборе без контента этапа 2 — 1, п. 5), `unit.<id>.ability.<имя>.on` (0/1) и `.<параметр>`, `tech.<id>.cost`,
`tech.branch.<ветка>.cost_mul`, `province.defense_mul`, `province.income_mul.<ресурс>`, `province.recruit_discount`.

**Ход.** Одно ребро — всегда; до `move` рёбер (наименьшее у юнитов приказа), если все промежуточные провинции свои;
стек только из `fast` — до `fast.range` рёбер через любую землю. В расчёте это движение из `from` в `to` (бой на ребре —
со встречным `to → from`), отход — в `from`. Ошибка — `NOT_ADJACENT` с подсказкой о дальности стека, и при дальности
1 (называет самый медленный юнит: «дальность этого стека — 1 ребро (у militia move 1)»).

**Способности в бою** (доля = доля юнитов со способностью в атаке стека, без множителей): `siege` — множитель обороны
провинции против этой доли не выше `siege.cap` (по умолчанию 1.0); `ignore_fortify` — бонус укрепления умножается на
(1 − доля); `garrison` — `+garrison.defense` к обороне юнита, когда он защищает провинцию своего владельца.
Множитель обороны провинции = `defense_mul` типа × `province.defense_mul`.

**Исследования.** Приказ `{"kind":"research","tech":"<id, короткий id или название ru/en>"}` — только в Д (в П1
проверка, в П2 `PHASE_LOCKED`, в том числе его отмена), один на книгу; меняется `amend_order(patch={"tech": ...})` в Д. Активная технология
остаётся активной между ходами, пока не изучена или не сменена (автопилот продолжает её). В шаге экономики после дохода,
содержания и голода запас ресурса роли `research` переходит в активную технологию, но не больше недостающего;
шаг «Исследования» (после строек) завершает её, когда прогресс ≥ цены (`tech.<id>.cost` × `cost_mul` ветки,
округление половины вверх); лишнее возвращается в запас. Требования: `requires` (все), `requires_any` (хоть одна),
`requires_tier {tier, count, same_branch=true}` (N изученных технологий яруса, своей ветки), `factions`. Ошибки:
`NOT_AVAILABLE`, `ALREADY_RESEARCHED`, `UNKNOWN_ID`, `INVALID` (второй приказ research). События расчёта (приватные):
`research_started {tech, progress}`, `tech_completed {tech, techs_count}`; у события `economy` — `research {tech,
added, progress, cost}`; в публичной части отчёта — `techs_count {seat: n}`, если в наборе есть технологии.

**Фаза старта.** Конфиг партии `setup {unique_factions, artifacts: draft|points|none, artifact_offer,
artifact_points, artifact_pool}` и `phase_limits.setup` (сценарий, иначе 300 с); нет ключа `setup` — фазы нет.
Сценарий: `setup: none` или объект с теми же полями (по умолчанию `unique_factions: true`, `draft`, 3, 3). Хост
переопределяет режим (`--artifacts`, `--artifact-offer`, `--artifact-points`, `--setup-limit`); `draft`/`points`
включают фазу и у сценария без неё. Состояние на время фазы — предварительное (фракции по умолчанию, без артефактов;
старты от фракций не зависят), `phase = "setup"`, ход 1. Драфт: из пула (сценария или все артефакты, допустимые
хоть одной фракции сценария) каждому месту по `artifact_offer` разных артефактов, без пересечений, если пула
хватает; раздаются только артефакты, доступные всем фракциям сценария, если таких не меньше `artifact_offer` (фракция
места ещё не известна — иначе слот мог оказаться пустым); из 64 раскладок по seed берётся та, где разброс суммы
`power` между местами наименьший. Очки: любые из пула,
сумма `cost` ≤ бюджета, без пар `exclusive_with`. Фракции: сначала выбравшие места в порядке жребия, затем остальные;
каждое берёт первую ещё не занятую из своих предпочтений, затем из списка сценария (при `unique_factions: false` —
первую из предпочтений). Умолчания: фракция места из конфига или первая свободная по списку сценария; драфт — первый
предложенный артефакт, доступный фракции; очки — артефакты пула по id, пока хватает бюджета. Артефакт не своей
фракции отбрасывается (в драфте заменяется умолчанием, в очках освободившийся бюджет — не больше цены отброшенных — добирается по умолчанию);
`choose_artifacts` и `choose_faction` предупреждают об этом сразу (`warning`, и в `text`), если выбор не подходит
первой из предпочтённых фракций. Закрытие: все нажали `ready` (confirm_hash необязателен,
если дан — `Game.setup_hash`) или лимит. Тогда ход 1 строится заново из итогов, пишется `private/setup.json` и
`private/states/turn_1.json`, журнал `setup_closed`, открывается П1.

**Журнал.** `setup_choice {seat, kind: factions|artifacts, factions|artifacts, turn, phase}` — приватно до
`setup_closed`; `setup_closed {turn, reason, factions{seat}, artifacts{seat}, results{seat: {faction, prefs, artifacts,
auto_faction, auto_artifacts, faction_conflict, dropped}}}` — фракции публичны, артефакты скрыты до `game_over`;
`research_started` / `tech_completed {seat, tech, turn}`. `dah replay` строит ход 1 из `results` события
`setup_closed`.

**Видимость.** `view_state`: у себя `you.techs`, `you.researching {tech, progress, cost}`, `you.research`,
`you.artifacts` (если в наборе есть технологии или артефакты); у всех игроков `faction`, а при технологиях —
`techs_count`; после `game_over` — ещё `techs` и `artifacts` каждого. Чужие технологии, прогресс и артефакты во время
партии не видны никому, кроме хоста (`admin_status`). Публичное число технологий (`techs_count` у игроков, в отчёте,
у зрителя, «тех.N» в строке счёта) не считает технологии, данные артефактами (`techs.public_techs`): иначе на ходу 1
оно выдавало бы выбор артефакта. Строка счёта текста состояния называет фракции игроков (если фракций больше одной и
фаза старта закрыта).

## 7. Как реализовано: API, мост, правила (шаг «API и мост»)

Где что: `server/app.py` (маршруты), `bridge/tools.py` и `bridge/client.py` (инструменты моста), `engine/rules.py`
(правила по темам), `game.py` (`rules`, фаза старта в `phase_info`/`get_state`, `estimate` со стороной места),
`waker/text.py` (пробуждение в фазе старта), `cli.py` (`goal_text`). Описание для игроков — `docs/*/http-api.md`,
`docs/*/connecting-agents.md`, `docs/*/rules.md`, `docs/CONNECT.md`.

**Маршруты** (все — ключ места): `GET /v1/setup` → `get_setup`; `POST /v1/setup/faction {prefs}` (или `factions`,
`faction`) → `choose_faction`; `POST /v1/setup/artifacts {ids}` (или `artifacts`, `artifact`) → `choose_artifacts`;
`GET /v1/techs` → `list_techs` (коротко: изученные, активная, доступные сейчас; `?full=true` — всё дерево); `GET /v1/describe?id=` (или `name=`) → `describe` (`404 NOT_FOUND`, если ничего не
нашлось). Выбор принимает список, одну строку, строку через запятую или JSON-строку. `POST /v1/ready` в фазе старта —
с пустым телом. `list_techs`, `describe` и всегда открытые `rules`, `whoami`, `phase`, `wait_phase` есть в `allowed`
всех фаз (и у выбывших). После закрытия фазы `get_setup` отдаёт пустые `factions` и `offer` (итог — `result`,
`players`). `describe` и `rules(topic)` принимают и начало названия («Литания»), если совпадений не больше пяти.

**Инструменты моста:** `get_setup()`, `choose_faction(prefs)`, `choose_artifacts(ids)`, `list_techs(full?)`,
`describe(id)` (примеры — с ID `core`; `get_setup` и `list_techs` отдают модели текст и малый JSON: выбор,
`confirm_hash`, итог / очки, доход, активная, изученные); `ready(confirm_hash?)` (без хэша — в фазе старта и в П1; в Д и П2 — `STALE_HASH` с точным вызовом `ready(confirm_hash="…")` и текущим `orders_hash`); `estimate(..., side?, opponent?)`; у
приказа — `kind: research` и поле `tech` (в `amend_order` — `patch {"tech"}`); `rules(topic)` перечисляет темы.
Сервер принимает и `{"kind":"research","technology":...}`.

**Фаза старта в `phase`/`get_state`.** `phase_info` в фазе `setup` добавляет `hint` (и в `text`). `get_state` в фазе
старта: текст начинается с «ФАЗА СТАРТА: состояние предварительное…», JSON получает `setup {open, provisional,
note}`, а `faction` всех, и своя, — `null` (предварительное состояние строится из умолчаний, но не должно выглядеть как
выбор), `you.faction_choice` — своя текущая первая из предпочтений; `whoami` так же.

**`estimate` места.** Необязательные `side` (`attacker` | `defender`) и `opponent` (ник): на стороне
`side` — `stat_key` вызывающего места, на другой — фракция `opponent` (публична; в фазе старта не берётся), без него —
фракция владельца чужой провинции, заданной ID, или базовые числа. Без `side` сторону определяют ID провинций: своя у
`defender` — `defender`, своя у `attacker` — `attacker`, чужая у `attacker` при составе-объекте у `defender` —
`defender`; иначе `attacker`. Ответ: `side` и `note` (чья сторона и почему); при `side: defender` и ID своей провинции — её `province_defense_mul`. Чужие здания не учитываются
(туман).

**Правила по темам** (`engine/rules.py`). Раздел — `Section(key, core, detail, short)`. `rules_text(ruleset, setup=,
extra=)` — заголовок, строка «ОГЛАВЛЕНИЕ» с темами партии и `core` всех разделов; если длиннее 6000, разделы по
очереди заменяются своим `short` (дипломатия → расчёт → провинции → здания → юниты), в крайнем случае текст
обрезается. `rules_topic(ruleset, topic)` — `detail` (или `core`) одной темы; темы: `turn, setup, resources,
provinces, units, abilities, buildings, orders, p2, combat, victory, pacts, fog, messages, techs, factions,
artifacts` и синонимы (`diplomacy`, `research`, заголовки разделов). `Game.rules(topic)` добавляет раздел
СООБЩЕНИЯ (лимиты партии), а ID или название контента отвечает описанием (`describe`); неизвестная тема — только
список тем (без ядра). Раздел `factions` в ядре —
только если фракций больше одной или есть фаза старта.

## 9. Как реализовано: боты, симулятор, зритель, отчёт (шаг «боты»)

Где что: `bots/choices.py` (выбор фракции, оценка артефактов, выбор технологии — чистые функции ответов
`GET /v1/setup` и `GET /v1/techs`), `bots/base.py` (фаза `setup` в цикле бота, приказ `research` в Д), `bots/view.py`
(таблицы чисел `core` 0.3.0, поля `you.faction/techs/researching/artifacts`), `bots/tactics.py` (`unique_recruit`),
`scripts/simulate.py`, `server/spectate.py` и `server/watch.html`, `report.py`, `waker/core.py` (`setup` — активная
фаза: участника будят и в фазе старта). Тесты — `tests/test_stage2_bots.py`, `tests/test_e2e_stage2.py`.

**Боты.** Стиль — атрибуты класса: `faction_style` (порядок фракций), `artifact_likes`, `branch_priority`,
`tech_first`. В фазе старта бот читает `get_setup()`, подаёт `choose_faction` (свой порядок, затем остальные фракции
сценария), `choose_artifacts` и жмёт `ready` без хэша; `passive` только жмёт `ready` (умолчания).

| Бот | Фракции | Любимые артефакты | Ветки | Сначала |
|---|---|---|---|---|
| `rush` | captains, growth, synclite, ash_choir, litany | mercenary_band, mercenary_contract, calm_banner, war_codex, seal_of_command | war, logistics, industry, mystery | drill_doctrine, surprise_doctrine |
| `builder` | litany, ash_choir, growth, captains, synclite | ore_vein, tithe_chalice, citadel_keystone, ancient_blueprint, smith_relic | industry, war, mystery, logistics | deep_drilling, agro_vats, fortification |
| `diplomat` | synclite, captains, ash_choir, litany, growth | seal_of_command, tithe_chalice, ore_vein, trail_maps, calm_banner | logistics, industry, mystery, war | treasury_order, staff_litanies |

Оценка артефакта: `power` + 1 за любимый (ранние в списке чуть дороже). Драфт — лучший из предложенных, доступных
первой фракции бота; очки — лучший набор в бюджете без пар `exclusive_with` (перебор до 4 штук). Исследование: в Д,
если активной технологии нет (`you.researching` пуст), бот берёт `list_techs()` и подаёт `research`: первая доступная
из `tech_first`, иначе доступная технология ветки с высшим приоритетом, старший ярус, затем дешевле. Найм: до 2
(`rush`) или 1 (`builder`, `diplomat`) уникального юнита своей фракции за ход перед штурмовиками (с учётом цены в
кредо и содержания). `builder` при технологиях ставит один Храм (на Святыне, иначе в столице), когда уже есть шахта и
провианта хватает, и Цитадель в столице после «Фортификации», если сплава ≥ 52. Числа ботов — `bots/view.py`
(сверка с паком — `test_bots_logic`, `test_stage2_bots`); модификаторы фракций боты не считают (сервер — авторитет).

**Симулятор.** Сценарий с фазой старта (или `--artifacts draft|points`) играет её в процессе теми же проверками, что
сервер (`check_faction_prefs`, `check_artifacts`, `resolve_setup`). `--factions rotate` (по умолчанию) раздаёт фракции
сценария (блок = полный оборот типов ботов по местам, так фракция не привязана к типу бота): блок берёт очередной
набор из стольких разных фракций, сколько мест (все наборы по очереди — каждая фракция встречает каждую одинаково
часто), порядок в наборе сдвигается; `--factions bots` — выбор ботов; список фракций через запятую — раздача по нему.
Карта на 4+ старта (`--scenario core:quad4`) берёт 4-местные конфигурации. Таблицы: победы по фракциям и артефактам,
у артефакта — прирост (`lift`: доля побед минус средняя) и прирост с поправкой (минус то, что предсказывают фракция и
тип бота держателей), доля партий с технологией яруса 2, технологий на место (по фракции и типу бота), самые
изучаемые технологии. Номинальный перевес в таблице боёв считается характеристиками сторон на начало расчёта
(фракция, технологии, артефакты), без множителей провинции, укрепления, способностей и случайности. `--json` (и
`--json-out FILE`) — `win_per_faction`, `seats_per_faction`, `win_per_artifact`, `seats_per_artifact`,
`artifact_lift`, `tier2_games`, `techs_per_faction`, `techs_per_seat` по конфигурациям и `ALL`.

Первый прогон (до прохода баланса; `quad4`, 144 партии, 3 конфигурации, раздача по кругу): Литания 57% побед на
место, Поросль 45%, Завет 12%, Капитаны 11%, Синклит 10%, Хор 10%; технологий за 12 ходов — 3.6–5.5 на место; артефакты
mercenary_band 42%, ore_vein 17%. Боты простые (нет ОК-стратегии и П2 у большинства), но перекос Литании и
Поросли виден — это вход для прохода баланса (SLICE.md, «Баланс `core` 0.3.0»).

**Зритель.** `live.setup {open, artifacts, unique_factions}` (у админа и ключа watch пока фаза открыта ещё `choices`
— выбор мест названиями). Снимки во время фазы старта — предварительного хода 1 (`provisional: true`) и не кешируются;
стартовые очки тоже. После закрытия фазы (или без неё, если фракций больше одной) у игроков снимка `faction` и
`faction_name` на всех уровнях (легенда показывает фракцию); `techs_count` — на всех уровнях, если в наборе есть
технологии; `techs`, `research`, `researching {tech, progress, cost}`, `artifacts` и словари `tech_names`,
`tech_branches`, `branch_names`, `artifact_names` — только на полных уровнях (админ вживую, после партии всем).
Зритель с задержкой выбора старта не видит никогда, артефакты и какие технологии — до конца партии. В `watch.html`:
фаза старта в шапке (режим артефактов), фракции в легенде, вкладка «Технологии» (полный уровень — изучено по веткам,
начатое, активное с прогрессом, артефакты; задержка — только число изученных), события `research_started` и
`tech_completed` в ленте с ником места.

**Отчёт.** `seats[s]` получает `faction`, `artifacts`, `auto_faction`, `faction_conflict` (из `setup_closed`; без фазы
старта — фракция конфига, если есть), `setup {artifacts, closed}`; в `totals[s]` — `setup_choices` и `techs [[ход,
id]]`; в `turns[]` — `techs_completed {seat: [id]}` и `research_started {seat: id}`. Текст: фракция и артефакты в
строке места, «изучено:» в строке хода, фаза старта как «СТАРТ». Отчёт — взгляд хоста (и зрителя после партии через
`timings`, закрытый для зрителя с задержкой).

## 10. Ревью этапа 2: что исправлено

Тесты — `tests/test_review_stage2.py`.

- **Агентам:** примеры моста — ID `core`; `get_setup`/`list_techs` в мосте — текст и малый JSON (вместо ~9–11 тыс.

## 11. Второе ревью этапа 2 (живые партии и спецификация)

Тесты — `tests/test_review_stage2_live.py`.

- **Ход в наборе без контента этапа 2.** `unit.<id>.move` по умолчанию — `Ruleset.move_default`: 2, если в наборе
  есть технологии, ветки или артефакты, иначе 1 (`registry.default_unit_move`). Признак выводится из хэшируемого
  контента и в хэш не входит, так `core` 0.2.0 и паки среза хэшируются по-прежнему, а идущая партия 0.2.0 снова ходит
  на одно ребро (до этого сервер этапа 2 принимал в ней ход на 2 ребра по своей земле). Текст правил при дальности 1
  не упоминает «по своей земле — до N рёбер».
- **`NOT_ADJACENT` всегда с дальностью:** и у стека с дальностью 1 — «дальность этого стека — 1 ребро (у militia
  move 1)»; называет самый медленный юнит.
- **Исследование закрыто после Д:** `cancel_order` приказа `research` в П2 — `PHASE_LOCKED` (раньше отмена за 1 ОК
  возвращала прежнюю активную технологию).
- **Скидка найма** (`province.recruit_discount`) — на одну единицу, цена единицы округляется вниз (в пользу игрока),
  затем × число: Склад делает штурмовика 9 сплава, а не 10, и три по одному стоят как три разом (п. 1.3).
- **Режим очков:** вместо отброшенного артефакта добирается не больше его цены; очки, которые игрок сам оставил
  неистраченными, не добираются.
- **Тексты:** строка «Твой выбор» в `get_setup` — короткие id с «названиями», а не список Python; `ready()` без хэша
  вне фазы старта — `STALE_HASH` «confirm_hash обязателен вне фазы старта: возьми orders_hash из list_orders (сейчас
  …)» вместо «набор приказов не совпадает».
- **Зритель:** приказ `research` в списке приказов — «исследование: <технология>»; на полном уровне «Изучено» во
